# 统一作品详情组件 · 设计文档

> 日期：2026-09-16
> 状态：待审阅
> 涉及模块：ASMR ONE / DLsite / 作品库

---

## 1. 背景与目标

ASMR ONE（`AsmrOnlineDetailPage.vue`，352 行）、DLsite（`DlsiteDetailPage.vue`，300 行）、作品库（`DetailPage.vue`，489 行）三个作品详情页各自维护了一套展示逻辑。经比对，三者的**封面块、返回按钮、RJ 行、标题区、元数据行、声优行、标签行、简介卡片、错误重试块**的模板逐字重复；`fakeView` 适配层在 ASMR ONE 与 DLsite 两处几乎逐字重复；「asmr.one 是否存在」的探测逻辑在 DLsite 与作品库两处重复。

本次目标：

1. 三个模块统一使用同一个作品详情组件。
2. 已入库、已下载等状态的展示统一复用作品库现有逻辑。
3. 作品存在于 ASMR ONE 时，优先按 ASMR ONE 作品逻辑展示。
4. 作品不存在于 ASMR ONE 时，按原 DLsite 作品逻辑展示。

### 非目标

- 不改动作品列表页、卡片组件、播放器页。
- 不改动 `TrackList.vue` 的既有 props 契约（仅通过既有 `online` / `tree` 开关驱动）。
- 不改动 asmr.one 文件树选择器 `AsmrFileTree.vue` 的内部实现。
- 不新增前端测试框架。

## 2. 关键设计结论

### 2.1 展示模式与来源模块正交

需求表格按「决定条件」重写后，「来源模块」这一列可以完全去掉：

| 模块 | 本地音频 | ASMR ONE 存在 | → 展示逻辑 |
|---|---|---|---|
| ASMR ONE | — | 是 | ASMR ONE |
| DLsite | — | 否 | DLsite |
| DLsite | — | 是 | ASMR ONE |
| 作品库 | 有 | 是/否 | 作品库本地 |
| 作品库 | 无 | 否 | DLsite |
| 作品库 | 无 | 是 | ASMR ONE |

因此展示模式只由三个条件决定：**来源是否为 ASMR ONE 页**、**本地是否有音轨**、**asmr.one 上是否存在**。组件不再需要依据来源做模板分支。

唯一的例外是 ASMR ONE 页面：其表格中「本地音频」列为「—」，即无论本地是否已下载，都走 ASMR ONE 逻辑。故组件保留一个显式的 `source` 参数用于强制模式，该参数只影响模式判定，不影响模板。

### 2.2 模式判定公式

```ts
type DetailMode = "local" | "asmr" | "dlsite";

mode =
  source === "asmr"                          ? "asmr"   // ASMR ONE 页恒为 asmr
  : source === "work" && localTracks.length  ? "local"  // 作品库且本地有音轨
  : hasOnline                                ? "asmr"   // 其余情况看 asmr.one 是否存在
  :                                            "dlsite"
```

`hasOnline`（是否探测到 asmr.one 作品）**独立于** `mode`：作品库本地有音轨时 `mode === "local"`，但仍需 `hasOnline` 决定是否显示「在线播放 / ASMR One下载」按钮。

### 2.3 探测策略的调整

当前作品库详情页的逻辑是「本地有音轨就不查 asmr.one」。本次**回退该策略**，改为始终探测 asmr.one 是否存在（仅调用 `/api/asmr/tracks` 判断有无音频，**不拉取文件树**）。

原因：按钮是否显示取决于 `hasOnline`，本地有音轨时同样需要该信息。未配置 `asmr_one_token` 时直接跳过探测。

**不拉取文件树的理由**：文件树数据量大（实测 RJ01609552 有 69 个节点），而「全部文件」标签页的用途是配合 `AsmrFileTree` 勾选下载，对已下载到本地的作品意义不大；且若拉取，同一张卡片的「音频 N」为本地数量、「全部文件 M」为在线数量，两个数字来源不同易被误读。

### 2.4 后端数据缺口与补齐

| 详情页数据源 | 现有本地状态字段 | 缺口 |
|---|---|---|
| `WorkView`（作品库） | `download_status`、`local_path`、`track_count` | 无 |
| `AsmrOnlineWork`（ASMR ONE） | `local_work_id` | 无 `download_status`、无本地音轨数 |
| `ScrapedWork`（DLsite） | 无 | 完全无本地库信息 |

补齐方式：新增按 RJ 查本地作品的接口，三个模块统一调用，作为本地状态的**单一来源**。

- 新增 `GET /api/works/by-rj/{rj}` → `WorkView | null`
- 复用已有 `queries::get_work_by_rj(&conn, rj)`（`server/src/db/queries.rs:182`）
- 前端新增 `api.getWorkByRj(rj)`

路由不冲突：`/api/works/{id}` 为 3 段、新路径为 4 段，axum 可区分。

ASMR ONE 页面已有 `AsmrOnlineWork.local_work_id`，但仍统一改用该接口，避免同一信息存在两条来源（`local_work_id` 保留，仅用于兜底）。

## 3. 组件划分

### 3.1 新增 `src/components/detail/WorkDetailView.vue`

纯展示外壳，**零请求**。只接收 props、只发出事件。

```ts
defineProps<{
  loading: boolean;
  error: string;
  // 头部
  title: string;
  subtitle?: string | null;          // 日文副标题
  rjCode?: string | null;
  coverUrl?: string | null;
  statusBadge?: StatusBadge | null;  // 已入库 / 已下载 / 下载中 / 未下载
  // 元数据
  meta: MetaItem[];                  // 图标 + 文本，按序渲染
  actors: string[];
  // 标签：本地有 TagEditor，在线只读
  tags?: Tag[];
  editableTags?: boolean;
  workId?: number | null;
  // 简介
  description?: string | null;
  descriptionNote?: string | null;   // 如「（来自 DLsite）」
  descriptionLoading?: boolean;
  // 按钮
  actions: DetailAction[];
  // 音轨区
  tracks?: Track[];
  trackWork?: WorkView | null;
  onlineTracks?: boolean;
  tree?: AsmrTreeNode[] | null;
  tracksLoading?: boolean;
  emptyTracksText?: string;
}>;

defineEmits<{
  (e: "retry"): void;
  (e: "tags-updated"): void;
  (e: "back"): void;
}>();
```

内部承载 `AsmrFileTree`（asmr.one 文件树下载选择器）与 `FolderPickerModal`（本地目录绑定选择器）两个 Modal——三个模块均需要下载与关联能力。

**外壳不含任何 `source === …` 分支**：所有按钮由 `useWorkDetail` 计算后以 `actions` 数组传入，所有元数据以 `meta` 数组传入。这是「三套逻辑合一」的关键约束。

### 3.2 新增 `src/composables/useWorkDetail.ts`

统一逻辑层。目前项目无 `composables/` 目录，本次新增。

职责：

- 按 `source` 拉取主数据（`getWork` / `asmrWorkDetail` / `previewByRj`）
- 探测 asmr.one 是否存在（`listAsmroneTracks`，失败即视为不存在）
- 按 RJ 查本地状态（`getWorkByRj`）
- 计算 `mode`、`hasOnline`、`statusBadge`、`meta`、`actions`
- 提供动作：在线播放、ASMR One 下载、入库、跳本地详情、打开 DLsite / ASMR One、播放全部、扫描音轨、关联本地、LLM 翻译、删除

导出形态：

```ts
export function useWorkDetail(opts: {
  source: "work" | "asmr" | "dlsite";
  id: Ref<string> | Ref<number>;   // 作品 id 或 RJ 号，响应式
}): {
  loading: Ref<boolean>;
  error: Ref<string>;
  mode: ComputedRef<DetailMode>;
  hasOnline: Ref<boolean>;
  view: Ref<WorkView | null>;      // 归一化后的统一视图
  displayTracks: ComputedRef<Track[]>;
  ...
};
```

`view` 是三种来源数据归一化后的 `WorkView`——即现有 `fakeView` 逻辑的唯一实现处（消除两份重复）。

### 3.3 三个路由改为薄壳

| 文件 | 变化 |
|---|---|
| `src/routes/DetailPage.vue` | 489 → 约 80 行 |
| `src/routes/AsmrOnlineDetailPage.vue` | 352 → 约 60 行 |
| `src/routes/DlsiteDetailPage.vue` | 300 → 约 60 行 |

每个薄壳只负责：调用 `useWorkDetail` → 把返回值绑定到 `WorkDetailView`。

## 4. 按钮矩阵

`本地文件夹` 按钮按需求移除（部署于 NAS，无需打开本地目录；`openLocal()` 将无调用点，一并移除）。

| # | 场景 | mode | 音轨区 | 按钮（从左到右） |
|---|---|---|---|---|
| 1 | ASMR ONE（存在） | asmr | 在线 | 在线播放 · 入库 \| 本地详情 · 下载 · DLsite · ASMR One |
| 2 | DLsite（不存在） | dlsite | 无卡片 | 入库 · DLsite |
| 3 | DLsite（存在） | asmr | 在线 | 在线播放 · 入库 \| 本地详情 · 下载 · DLsite · ASMR One |
| 4 | 作品库·本地有·存在 | local | 本地（不拉树） | 播放 · 下载 · 扫描音轨 · 关联本地 · LLM 翻译 · 在线播放 · ASMR One下载 · DLsite 页面 · ASMR One · 删除 |
| 4b | 作品库·本地有·不存在 | local | 本地 | 同 4，去掉「在线播放 / ASMR One下载」 |
| 5 | 作品库·本地无·不存在 | dlsite | 「暂无音轨」卡片 | 下载 · 扫描音轨 · 关联本地 · LLM 翻译 · DLsite 页面 · ASMR One · 删除 |
| 6 | 作品库·本地无·存在 | asmr | 在线 | 在线播放 · ASMR One下载 · 下载 · 扫描音轨 · 关联本地 · LLM 翻译 · DLsite 页面 · ASMR One · 删除 |

### 4.1 按钮规则明细

- **在线播放**：`hasOnline` 为真时显示。文案由「在线试听」改为「在线播放」。
- **入库**：`hasOnline && !localWorkId` 时显示。`localWorkId` 非空时改为显示「本地详情」。（两者均仅 `source !== 'work'` 时适用）
- **下载**（asmr.one）：`hasOnline` 时显示。点击后静默入库 → 打开 `AsmrFileTree` 勾选文件 → 下载。选完不跳转，留在当前页并刷新本地状态。
- **播放**：仅 `mode === 'local'` 且有本地音轨时显示（`asmr` 模式下与「在线播放」重复）。
- **下载**（DLsite 压缩包直链）：`source === 'work'` 时**始终**显示（决策 13）。本地无音频时该按钮尤其必要——那是用户取得文件的主要途径。
- **扫描音轨 / 关联本地 / LLM 翻译 / 删除**：仅作品库（`source === 'work'`）显示——作品库身份叠加在来源模式之上，不被来源模式取代。这三项在本地无音频时尤其必要（`关联本地` 是本地无音频时唯一的补救入口）。
- **入库 / 本地详情**：仅 `source !== 'work'` 时显示。`hasLocalWork` 为真显示「本地详情」，否则在 `hasRj` 为真时显示「入库」。作品库页面自身不显示这两个按钮（已在本地详情页）。
- **DLsite 页面**：外链，按 `rj_code` 是否存在显示（三个模块统一）。
- **ASMR One**：外链。作品库与 ASMR ONE 页无条件显示（现状）；DLsite 页保持现状 `hasOnline` 条件显示。统一后规则简化为：`source === 'dlsite' ? hasOnline : true`，即仅在 DLsite 页受 asmr.one 存在性约束。

### 4.2 「下载」按钮命名（已确认方案 a）

作品库场景 4/6 会同时存在两个下载按钮：DLsite 压缩包直链「下载」与 asmr.one 文件树下载。

- 作品库内：asmr.one 下载按钮命名为 **「ASMR One下载」**
- ASMR ONE / DLsite 页内：命名为 **「下载」**

各页面内部无歧义，且符合需求原文文案。

## 5. 后端改动

### 5.1 新增接口

`server/src/main.rs` 路由表新增：

```rust
.route("/api/works/by-rj/{rj}", get(handlers::works::get_work_by_rj))
```

`server/src/handlers/works.rs` 新增 handler，形态与既有 `get_work`（`works.rs:51`）一致：

```rust
pub async fn get_work_by_rj(
    State(state): State<SharedState>,
    Path(rj): Path<String>,
) -> Result<Json<Option<WorkView>>, AppError>
```

内部 `spawn_blocking` → `queries::get_work_by_rj` 取 `Work` → 调用 `queries::work_view(&conn, work)`（`queries.rs:145`，即 `get_work` 内部使用的同一函数）组装完整 `WorkView`，保证 `download_status`、`track_count`、`tags`、`actors`、`group` 与作品库详情页完全一致。

RJ 号大小写不敏感：`queries::get_work_by_rj` 已使用 `COLLATE NOCASE`。

### 5.2 前端 API

```ts
export function getWorkByRj(rjCode: string): Promise<WorkView | null> {
  return get(`/api/works/by-rj/${encodeURIComponent(rjCode)}`);
}
```

### 5.3 不改动

`AsmrOnlineWork` 结构体、`ScrapedWork` 结构体、下载引擎、`/api/download/asmr` 接口均不改动。静默入库复用既有 `/api/import/by-rj`。

## 6. 下载流程

三个模块的 asmr.one「下载」按钮共用同一流程：

1. 点击 → 若 `localWorkId` 为空：调用 `api.importByRj(rjCode)` 静默入库，取得 `work.id`
2. 刷新本地状态（重新调用 `getWorkByRj`），使「入库」按钮变为「本地详情」
3. 打开 `AsmrFileTree`，拉取文件树并默认全选音频/字幕
4. 用户确认 → `api.downloadAsmroneFiles(workId, files)` → 提示前往「下载管理」
5. 留在当前页，不跳转

未配置 `asmr_one_token` 时，在第 1 步之前提示「请先在「设置 -> asmr.one」登录获取 Token 后再试」。

## 7. 状态展示统一

`statusBadge` 由 `useWorkDetail` 统一计算，取值复用作品库现有语义：

| 条件 | 角标 | 样式 |
|---|---|---|
| `download_status === 'downloaded'` | 已下载 | 绿 |
| `download_status === 'downloading'` | 下载中 | 强调色 |
| 已入库但未下载 | 未下载 | 中性 |
| 未入库且 asmr.one 存在 | 未入库 | 黄（沿用 ASMR ONE 页现有样式） |

`已入库` 的判定统一为 `localWorkId != null`。ASMR ONE 页面现有的「已入库」角标（可点击跳本地详情）保留该交互。

## 8. 音轨区规则

| mode | 数据源 | `TrackList` props | 标签栏 |
|---|---|---|---|
| `local` | 本地音轨 | `:tracks="localTracks"` | 无 |
| `asmr` | 在线音轨 + 文件树 | `:tracks="onlineTracks" online :tree="tree"` | 音频 / 全部文件 |
| `dlsite` | 无 | 不渲染卡片 | — |

`mode === 'dlsite'` 时：作品库场景显示「暂无音轨。下载并解压作品后会自动扫描。」空状态卡片；DLsite 场景完全不渲染音轨卡片（保持该页现状）。

`trackWork` 在 `asmr` 模式下使用在线音轨数与总时长，但保留真实 `work.id`（`mode === 'local'` 时为本地 `WorkView` 原值），确保 `TrackList` 的「当前播放」高亮能正确匹配。

## 10. 风险与权衡

| 风险 | 说明 | 缓解 |
|---|---|---|
| 三个页面功能多，合并易丢功能 | 作品库有 11 个按钮，ASMR ONE 有 5 个 | 第 4 节矩阵逐格核对；重构前截图基线；逐场景浏览器验证 |
| 新增探测请求 | 作品库本地有音轨时也探测 asmr.one | 仅调用 `/api/asmr/tracks`，不拉文件树；无 token 时跳过 |
| `composables/` 目录为项目新增结构 | 项目原无该目录 | 可改放 `src/lib/workDetail.ts`；本设计采用 `composables/` |
| 无前端测试框架 | 组件与交互回归依赖人工验证 | 模式判定与按钮矩阵抽为纯函数，用 Node 内置 `node:test` 做 TDD（无需新依赖）；组件层以浏览器验证覆盖 |
| 三份 `fakeView` 归一化逻辑 | 字段映射细节多，易出错 | 集中到 `useWorkDetail` 单处实现，消除两份重复 |
